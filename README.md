# EDH Primers

Complete EDH deck reports generated by **MTG Commander Builder** (Scryfall + EDHREC + Commander Spellbook).

🌐 **Online index** : https://chakkrachak.github.io/edh-primers/

Each primer contains: the commander sheet (verified Oracle text, SVG mana symbols), the chosen game plan with a secondary source, cards by EDHREC categories (synergy badges, explanations verified against the Oracle) and relevant combos filtered by color identity. **All content is in English** — Oracle texts and Commander Spellbook combo data are reproduced verbatim in their original language.

## Structure

```
├── index.html          ← landing page (commander cards)
├── css/
│   ├── theme.css       ← shared tokens (colors, shapes, typography)
│   ├── index.css       ← index styles
│   └── report.css      ← report styles (sheet, categories, combos)
├── data/               ← CONTENT (editable, one JSON per deck)
│   ├── decks/*.json    ← commander sheet, explanations, plans, combos, synergy
│   └── index.json      ← index texts (titles, descriptions)
├── templates/          ← STRUCTURE (HTML layouts)
│   ├── report.html     ← report layout ({{ vars }}, {% for %}, {% if %})
│   └── index.html      ← index layout
├── build/
│   └── render.py       ← mini template engine (zero dependency)
├── build.py            ← assembler: data/ + templates/ → content/ + index.html
└── content/            ← the generated reports (one HTML per commander)
```

**Separation of concerns**: content lives in `data/` (plain JSON), structure in `templates/`
(small custom template engine, see `build/render.py`), styling in `css/`. To change anything:
- a card explanation → edit `data/decks/<slug>.json`
- a layout section → edit `templates/report.html`
- colors/spacing → edit `css/` (no regeneration needed — reports load CSS at runtime)

**Regenerate**: `python3 build.py` (all decks) or `python3 build.py <slug>` (one deck).
The old `regen_*.py` scripts and `report_gen.py` were replaced by this pipeline
(archived in `/opt/data/archive_legacy/`).

The site is **100% static**: no inline CSS — the index loads `css/theme.css` + `css/index.css`, each report loads `css/theme.css` + `css/report.css`. Any new report generated by `build.py` references these files automatically.
